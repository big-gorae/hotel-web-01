# 호텔 이상현상 바이블

이 디렉터리는 확정된 이상현상의 서사와 핵심 기믹을 이상현상별로 관리한다. 구현 수치가 바뀌더라도 각 문서에서 **확정**으로 표시한 인과관계와 플레이 경험은 유지한다.

사용자가 명시적으로 확정한 전체 결정과 최근 변경 사항은 [확정 사항 원장](confirmed-decisions.md)에서 한 번에 확인한다. 이상현상 처리 입력과 진행 바 규칙은 [이상현상 진행 바](interaction-progress.md)를 따른다.

이상현상 처리에 사용되거나 처리 이후 위험 상태로 변하는 아이템은 [이상현상 아이템](items/README.md)에서 관리한다.

확정된 내용을 코드와 이미지로 옮기는 구조, 제작 순서와 SceneLock 인수인계 방식은 [이상현상 구현 문서](../implementation/README.md)에서 관리한다.

## 분류

이상현상은 **엔티티**와 **기현상** 두 묶음으로만 나눈다.

- **엔티티**: 의지와 공격성을 가진 존재가 직접 개입하는 강한 이상현상. 고유 이름, 서사, 복합 대응법과 전용 연출을 가진다.
- **기현상**: 존재가 직접 출현하지 않고 객실이나 설비 상태만 작게 어긋나는 이상현상. 발견 후 한 가지 호텔 관리 행동으로 쉽게 처리한다.

엔티티와 기현상은 위험도 등급이 아니라 **존재의 직접 개입 여부와 처리 방식**을 구분하는 분류다.

## 공통 정사

- 호텔에 나타나는 귀신은 악의를 지니며 이 공간에 있는 사람을 죽이고 싶어 한다.
- 플레이어는 귀신을 퇴마하지 않는다. 규칙을 지켜 살아남거나, 출현 조건을 일시적으로 억제할 뿐이다.
- 이상현상을 손님으로 인식하거나 숙박부에 등록해 붙잡는 방식은 사용하지 않는다.
- 호텔의 관리자는 정체를 알 수 없는 인물이며 룰북의 모든 규칙을 제정한다.
- 룰북은 처음에는 평범한 관리 규칙만 제시하고, Day가 진행될수록 이상현상에 대응하는 수상한 규칙을 추가한다.
- 이상현상의 정체를 UI 메시지로 직접 설명하지 않는다. 환경, 행동 결과, 소리와 룰북 문장으로 이해하게 한다.
- 활성 이상현상은 항상 최대 1개다. 본편의 Day 진행과 순차 발생 원칙은 [7일 야간 근무 구조](../night-structure.md)를 따른다.

## 기현상

확정된 기현상 15종의 장소, 최소 등장 Day, 처리법과 개별 문서는 [기현상 인덱스](phenomena/README.md)에서 관리한다.

정사로 확정되기 전의 아이디어는 [이상현상 후보 목록](candidates.md)에 별도로 보관한다.

## 문서 상태 표기

- **확정**: 이후 구현에서도 유지해야 하는 서사 또는 기믹.
- **튜닝값**: 플레이 테스트에 따라 숫자를 바꿀 수 있는 시간, 간격, 횟수.
- **미정**: 아직 정사로 확정하지 않은 정체, 외형, 사건의 원인.
- **현재 프로토타입**: 게임에 이미 들어가 있지만 최종 정사나 연출과 다를 수 있는 동작.

새 이상현상을 확정하면 이 표에 추가하고, 한 이상현상에 속한 전조와 형상은 가능하면 같은 문서에서 함께 관리한다.
