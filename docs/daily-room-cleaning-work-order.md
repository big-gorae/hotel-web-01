이 문서는 프런트의 객실 정리 명부, 그날 출입 가능한 객실, 객실별 고정 일감, 일감과 엔티티·기현상의 충돌 방지 규칙을 정의한다.

## 핵심 경험

플레이어는 매일 프런트에서 명부를 확인한다. 명부에는 해야 할 행동을 적지 않고, 그날 정리해야 하는 객실 번호만 적혀 있다.

플레이어는 반복 근무를 통해 각 객실에서 무엇을 정리해야 하는지 스스로 익힌다. 익숙한 업무와 동선을 반복하는 도중 평소와 다른 객실 상태를 발견하고, 룰북에 따라 엔티티와 기현상에 대응한다.

핵심은 다음과 같다.

1. 명부는 **목적지**만 알려 준다.
2. 객실 안의 일감은 UI 목록으로 설명하지 않는다.
3. 같은 객실에는 같은 일감이 반복되어도 된다.
4. 반복을 통해 정상 상태를 외우게 하고, 기현상의 차이를 알아차리게 한다.
5. 엔티티와 기현상이 등장하는 객실은 반드시 그날 명부에 포함한다.
6. 일감과 이상현상은 같은 물체·핫스폿·상호작용 표면을 사용하지 않는다.

## 하루의 기본 흐름

1. 플레이어는 프런트에서 근무를 시작한다.
2. 프런트 명부를 눌러 그날 정리할 객실 번호를 확인한다.
3. 명부에 없는 객실은 `Do not disturb` 상태로 잠겨 있다.
4. 명부에 있는 객실을 1차로 순회한다.
5. 객실의 일반 정리와 함께 쓰레기와 욕실의 풀어진 수건을 수거한다.
6. 수거한 쓰레기는 외부 계단의 폐기 장소에 정리한다.
7. 수거한 수건은 세탁실의 일반 세탁기로 한 번에 세탁한다.
8. 세탁한 수건을 들고 객실을 2차로 순회해 제자리에 정리한다.
9. 프런트로 돌아와 명부를 다시 누른다.
10. 완료된 객실 번호를 펜으로 하나씩 지운다.
11. 모든 객실 번호가 지워지면 `업무 완료` 버튼이 활성화된다.
12. `업무 완료`를 누르면 그날 근무를 종료하고 다음 Day로 넘어간다. 고정 사건은 객실 정리 동선 안에서 그 전에 모두 발생하고 해결되어야 한다.

이 구조는 객실, 복도, 외부 계단, 세탁실과 프런트를 한 근무 안에서 자연스럽게 왕복하게 한다.

## 프런트 명부

### 처음 확인할 때

- 명부는 프런트 숙박부 또는 별도 업무 명부 핫스폿으로 연다.
- 종이에는 `오늘 정리할 객실`과 객실 번호만 표시한다.
- `이불 정리`, `쓰레기 정리` 같은 일감 이름은 표시하지 않는다.
- 처음 열었을 때 모든 객실 번호는 지워지지 않은 상태다.
- `업무 완료` 버튼은 비활성 상태다.
- 명부를 읽지 않고 프런트를 떠나는 행동을 강제로 막지는 않는다. 객실 출입 권한은 이미 그날 명부를 기준으로 적용되어 있다.

예시:

```text
오늘 정리할 객실

105
107

[업무 완료]
```

### 업무 후 다시 확인할 때

- 명부를 열면 `완료되었지만 아직 명부에서 지우지 않은 객실`을 객실 번호 순서대로 처리한다.
- 객실 번호마다 짧은 펜 긋기 애니메이션과 종이를 긁는 소리를 한 번 재생한다.
- 여러 객실을 완료했더라도 동시에 지우지 않고 하나씩 지운다.
- 아직 일감이 남은 객실은 아무 설명 없이 지워지지 않은 상태로 남는다.
- 별도 팝업, 토스트, `아직 쓰레기가 남아 있습니다` 같은 정답 설명을 표시하지 않는다.
- 모든 객실 번호가 지워진 직후 `업무 완료` 버튼을 활성화한다.

### 업무 완료 버튼

- 활성 조건은 명부의 모든 객실 번호가 실제로 지워진 상태인 것이다.
- 버튼 활성화 전에 모든 객실의 일반 일감이 완료되어 있어야 한다.
- 활성 엔티티나 기현상이 프런트 입력을 점유하고 있다면 명부 상호작용을 잠시 받지 않는다.
- 버튼은 그날 근무 종료를 의미한다.
- 예정된 스토리 사건이나 production 사건이 남아 있는 상태에서 모든 일반 일감만 끝나는 일정은 만들지 않는다.
- Day 7의 109호 결말은 현재 확정 흐름대로 프런트에서 복도로 처음 나갈 때 먼저 진행하고, 해결 후 일반 객실 정리를 이어 간다.

## 객실 출입과 `Do not disturb`

### 출입 원칙

- 일반 객실 범위는 105~108호다.
- 그날 명부에 포함된 객실만 출입할 수 있다.
- 명부에 없는 객실은 문을 눌러도 이동하지 않는다.
- 세탁실은 명부에 적지 않으며 항상 출입할 수 있다.
- 프런트, 복도와 외부 계단도 항상 출입할 수 있다.
- 109호는 일반 객실 정리 명부에 포함하지 않는다. 기존 109호 사건의 상태가 출입 가능 여부를 별도로 결정한다.

### 최근 구현의 재사용

`eab8ab3`에서 닫힌 109호에 적용한 다음 방식을 일반 객실 잠금에도 사용한다.

1. 출입 가능한 문에는 기존 이동 핫스폿과 `target`을 유지한다.
2. 출입 불가능한 문에는 이동 핫스폿 대신 `target`이 없는 잠긴 문 핫스폿을 제공한다.
3. 잠긴 문을 누르면 `locked_door_handle` 소리를 재생한다.
4. 화면 하단 중앙에 `"'Do not disturb'가 걸려 있다"`를 짧게 표시한다.
5. 현재 장면은 복도에 그대로 유지한다.

109호 전용 상수 하나를 객실 전체에 복사하는 대신, 객실별 문 핫스폿과 사각형을 데이터로 관리한다.

```gdscript
const GUEST_ROOM_DOORS := {
	"room_105": {"hotspot_id": "room_105_locked_door", "rect": Rect2(...)},
	"room_106": {"hotspot_id": "room_106_locked_door", "rect": Rect2(...)},
	"room_107": {"hotspot_id": "room_107_locked_door", "rect": Rect2(...)},
	"room_108": {"hotspot_id": "room_108_locked_door", "rect": Rect2(...)},
}
```

모든 객실 진입은 한곳의 권한 판정을 거친다.

```gdscript
func can_enter_room(room_id: String) -> bool:
	return work_order_manager.is_room_assigned(room_id)
```

복도 문뿐 아니라 프런트의 객실 바로가기, 디버그가 아닌 다른 이동 핫스폿과 이후 추가되는 모든 진입 경로에도 같은 판정을 적용한다. UI 하나만 막고 다른 경로로 입장할 수 있는 상태를 허용하지 않는다.

### 이상현상과 출입 권한의 우선순위

1. Day 7의 109호처럼 사건이 직접 문 상태를 제어하면 사건 규칙을 우선한다.
2. 108호 전화처럼 일시적인 진입 금지 사건이 활성화되면 사건의 사망 판정을 우선한다.
3. 그 외 일반 객실은 명부 포함 여부로 출입을 결정한다.
4. 이상현상 예정 객실이 명부에서 빠지는 일정은 데이터 검증 단계에서 오류로 처리한다.

## 확정 일감 여섯 종류

명부에는 아래 이름을 표시하지 않는다. 플레이어는 객실 사진에 남아 있는 평범한 정리 대상을 직접 찾아 처리한다.

### 1. 이불 정리

- 대상: 평평하지만 흐트러진 일반 침대 이불
- 입력: 이불 전체를 짧게 길게 누름
- 결과: 각이 잡힌 정상 이불 사진으로 교체
- 사용 객실: 기본적으로 105호와 108호
- 금지: `이불 속 아이`가 선택된 객실에는 배정하지 않는다.
- 금지: 이불 위나 침대 영역을 점유하는 엔티티와 같은 Day·객실에는 배정하지 않는다.

### 2. 쓰레기 정리

- 대상: 객실 바닥이나 협탁 주변의 종이, 컵과 작은 쓰레기
- 입력: 보이는 쓰레기를 각각 눌러 작업용 쓰레기봉투에 수거
- 결과: 쓰레기 레이어 제거
- 최종 단계: 그날 객실들의 쓰레기를 외부 계단의 폐기 장소에 한 번에 정리
- `collected_trash`는 Hand 슬롯을 차지하지 않는 업무 화물로 관리한다.

쓰레기 폐기 동선은 외부 계단의 `지옥으로 향하는 비상 화살표`를 자연스럽게 발견하게 한다.

### 3. 욕실에 걸려 있지 않은 수건 정리

- 대상: 욕실 바닥, 선반 또는 세면대 옆에 놓인 풀어진 수건 뭉치
- 수건걸이에 걸린 수건은 일반 일감 대상으로 사용하지 않는다.
- 1차 방문에서 더러운 수건을 수거한다.
- 세탁 후 2차 방문에서 깨끗한 수건을 지정된 선반에 정리한다.
- 수건 수거와 반환 상태는 객실별로 따로 저장한다.

인간 가죽 수건은 수건걸이를 전용 표면으로 사용하고, 일반 일감은 걸려 있지 않은 별도 수건 뭉치를 사용하므로 서로 겹치지 않는다.

### 4. 옷장에 남은 옷 수거

- 대상: 열린 옷장 안에 보이는 셔츠나 외투
- 입력: 옷을 눌러 분실물 봉투에 수거
- 결과: 옷만 사라지고 옷장 배경은 유지
- 기본 사용 객실: 107호
- 105호에는 배정하지 않는다.
- 돼지 가면 남자가 선택된 객실에는 절대 배정하지 않는다.
- 회수한 옷은 Hand 슬롯이 아닌 분실물 업무 화물로 관리한다.

### 5. 피 묻은 벽 닦기

- 대상: 거울, 욕조, 문 아래와 떨어진 일반 벽면의 작고 마른 얼룩
- 입력: 청소용 천을 장착하고 얼룩 전체를 길게 누름
- 결과: 얼룩 레이어가 사라지고 마른 천 마찰음 재생
- 기본 사용 객실: 106호
- 빨간 손자국 거울과 같은 사진을 사용하더라도 벽 얼룩과 거울 핫스폿은 겹치지 않게 한다.

일반 벽 얼룩은 항상 같은 위치와 작은 크기로 반복된다. 기현상의 피 웅덩이와 손자국은 넓고 비정상적인 형태로 구분한다.

### 6. 세탁실에서 수건 빨기

- 조건: 그날 명부에 있는 모든 객실에서 더러운 수건을 수거함
- 대상: 붉은 세탁기 사건이 사용하지 않는 일반 세탁기
- 입력: 수거한 수건을 넣고 일반 세탁을 시작
- 결과: 그날 분량을 한 번에 세탁하고 `clean_towel_bundle` 업무 화물 획득
- 이후 각 객실 욕실로 돌아가 깨끗한 수건을 정리해야 한다.

붉은 세탁기는 전용 세탁기를 사용한다. 일반 수건 세탁과 붉은 세탁기가 같은 기계·핫스폿·사진 상태를 공유하지 않는다. 붉은 세탁기 사건이 활성 상태인 동안 일반 세탁 입력은 잠시 숨기고, 사건 해결 후 다시 제공한다.

## 객실별 기본 일감 프로필

객실이 명부에 포함되면 아래 일감이 반복된다. 이 반복은 정상 상태 학습을 위한 의도된 설계다.

| 객실 | 매번 반복하는 기본 일감 | 사용하지 않는 일감 | 이유 |
| --- | --- | --- | --- |
| 105호 | 이불 정리, 쓰레기 정리, 풀어진 수건 수거·세탁·반환 | 옷장 옷 수거 | 돼지 가면 남자의 옷장과 완전 분리 |
| 106호 | 쓰레기 정리, 풀어진 수건 수거·세탁·반환, 피 묻은 벽 닦기 | 옷장 옷 수거 | Day 6 욕실을 두 번 방문하도록 구성 |
| 107호 | 쓰레기 정리, 풀어진 수건 수거·세탁·반환, 옷장 옷 수거 | 이불 정리 | 매달린 여자아이와 빈 로프의 침대·천장 영역 보존 |
| 108호 | 이불 정리, 쓰레기 정리, 풀어진 수건 수거·세탁·반환 | 옷장 옷 수거 | 욕조와 TV 등 이상현상 표면을 피함 |

모든 객실의 수건을 모아 하루에 한 번만 세탁한다. 이 때문에 최소 두 번의 객실 순회가 생기고, 첫 방문 뒤에 준비된 두 번째 이상현상을 자연스럽게 발견할 수 있다.

## 스토리 모드의 일일 객실 명부

스토리 모드는 무작위로 객실을 바꾸지 않고 아래 명부를 사용한다.

| Day | 명부에 적힌 객실 | 그날 주요 사건 | 충돌 방지와 조우 동선 |
| ---: | --- | --- | --- |
| 1 | 105, 106 | 없음 | 기본 순회, 쓰레기 폐기와 수건 세탁을 학습 |
| 2 | 105, 107 | 105호 돼지 가면 남자, 복도 빨간 객실등 | 105호에는 옷장 일감이 없음. 객실 이동 중 빨간 조명 발견 |
| 3 | 107, 108 | 107호 매달린 여자아이 | 107호에는 이불 일감이 없음. 수건 세탁을 위해 세탁실에서 귀여운 인형 발견 |
| 4 | 108, 105 | 108호 전등 수리 전화, 따라오는 그림자 | 108호 일감을 먼저 완료한 뒤 프런트 복귀 시 전화를 시작. 이동 반복이 그림자 조우 동선이 됨 |
| 5 | 108, 106 | 붉은 세탁기, 108호 욕조의 내장 | 108호의 풀어진 수건이 욕실 진입 이유가 됨. 일반 세탁기는 붉은 세탁기와 분리 |
| 6 | 106, 107 | 106호 등록되지 않은 아이, 106호 끔찍한 거울 | 106호 수건 수거와 반환으로 욕실을 두 번 방문. 첫 방문은 아이, 두 번째 방문은 거울에 사용 |
| 7 | 105, 108 | 109호 통과 | 프런트에서 복도로 처음 나갈 때 109호 결말을 먼저 진행. 해결 후 객실 정리를 시작하며 109호는 명부에 넣지 않음 |

### Day 4 전화 순서

108호 전등 수리 전화는 108호의 일반 일감이 완료되기 전에 시작하지 않는다.

1. 플레이어가 108호를 정리한다.
2. 수건 반환까지 마쳐 108호를 완료한다.
3. 플레이어가 프런트로 돌아온다.
4. 명부를 누르기 전에 전화가 울린다.
5. 전화를 받은 뒤 108호 진입 금지 시간이 시작된다.
6. 이미 108호 일감이 끝났으므로 업무와 사건의 요구가 충돌하지 않는다.

### Day 6 두 번의 욕실 방문

Day 6에는 같은 106호 욕실에서 두 사건이 순차적으로 일어나므로 일감 동선을 명시적으로 사용한다.

1. 첫 욕실 방문에서 등록되지 않은 아이를 만난다.
2. 아이를 진정시킨 뒤 바닥이나 선반의 더러운 수건을 수거한다.
3. 106호를 나가 세탁실에서 수건을 세탁한다.
4. 깨끗한 수건을 돌려놓으러 106호 욕실에 다시 들어간다.
5. 두 번째 방문에서 끔찍한 화장실 거울을 발견한다.
6. 거울을 처리한 뒤 깨끗한 수건을 정리한다.

두 사건은 동시에 활성화하지 않는다. 두 번째 사건은 플레이어가 첫 사건을 해결하고 106호 욕실 화면을 떠난 뒤에만 준비한다.

### 활성 사건이 있는 장면의 입력 우선순위

같은 사진에 안전한 일반 일감이 있더라도 엔티티나 기현상이 활성화된 동안에는 일반 일감 핫스폿을 숨긴다.

1. 사망·긴급 대응 입력
2. 활성 엔티티 또는 기현상 입력
3. 장면 이동 입력
4. 일반 일감 입력
5. 평범한 조사 대사 입력

사건을 해결하고 정상 사진이 복구된 뒤 일반 일감 핫스폿을 다시 노출한다. 이상현상 해결 입력이 일감 완료로 잘못 처리되거나, 일감 처리 중 이상현상 핫스폿이 가려지는 상태를 허용하지 않는다.

## 객실 완료 판정

객실은 아래 조건을 모두 만족하면 내부적으로 `complete`가 된다.

1. 객실의 즉시 완료 일감이 모두 끝났다.
2. 객실에서 발생한 쓰레기를 모두 수거했다.
3. 수거한 쓰레기를 외부 폐기 장소에 정리했다.
4. 욕실의 더러운 수건을 수거했다.
5. 그날의 수건 세탁을 완료했다.
6. 깨끗한 수건을 해당 객실 욕실에 돌려놓았다.

엔티티나 기현상 해결 자체는 호텔 일감으로 계산하지 않는다. 다만 활성 사건이 일반 일감 입력을 점유하므로, 실제 플레이에서는 사건을 처리해야 객실 정리를 계속할 수 있다.

객실이 내부적으로 완료되어도 복도나 HUD에 완료 표시를 띄우지 않는다. 프런트 명부를 다시 열었을 때만 펜으로 번호를 지운다.

## 시스템 구조

### `HotelWorkOrderDefinition`

스토리 Day 또는 Infinity 한 근무의 객실 목록을 정의한다.

```gdscript
var day := 1
var room_ids: Array[String] = []
var room_task_ids: Dictionary = {}
var completion_event_id := ""
```

### `HotelWorkOrderManager`

책임:

- 그날 명부의 객실 목록 보관
- 객실별 일감 완료 상태 계산
- 객실 출입 가능 여부 제공
- 명부에서 이미 지운 객실과 새로 지울 객실 구분
- `업무 완료` 버튼 활성 조건 제공
- 스토리 고정 명부와 Infinity 생성 명부 모두 지원
- 세이브 상태 내보내기와 복구

권장 API:

```gdscript
func start_day(definition: HotelWorkOrderDefinition) -> void
func get_assigned_room_ids() -> Array[String]
func is_room_assigned(room_id: String) -> bool
func is_room_work_complete(room_id: String) -> bool
func get_uncrossed_completed_room_ids() -> Array[String]
func mark_room_crossed(room_id: String) -> void
func can_finish_work() -> bool
func export_state() -> Dictionary
func import_state(state: Dictionary) -> void
```

기존 `HotelTaskManager`는 개별 일감의 상태와 행동을 계속 담당하고, `HotelWorkOrderManager`는 Day별 활성 일감, 객실 묶음과 명부 상태를 담당한다.

### 일감 상태

기존 `pending`과 `done`만으로는 수건 왕복을 표현하기 어렵다. 다단계 일감은 다음 상태를 사용한다.

- `pending`: 아직 시작하지 않음
- `collected`: 객실에서 수거함
- `processing`: 세탁 중
- `ready_to_return`: 세탁 완료, 객실 반환 필요
- `done`: 객실에 반환 또는 정리 완료

일반 일감이 활성 사건 때문에 잠시 입력되지 않는 상태는 별도 실패 상태로 저장하지 않는다. 사건이 해결되면 기존 상태를 그대로 이어 간다.

### 업무 화물과 Hand 분리

다음은 Hand 장착 아이템으로 취급하지 않는다.

- 객실 쓰레기
- 더러운 수건 묶음
- 깨끗한 수건 묶음
- 손님이 두고 간 옷

이들은 `work_cargo` 상태로 관리한다. 작은 거울, 청소용 천과 귀여운 인형 같은 이상현상 관련 Hand 아이템과 업무 물건이 서로 밀어내지 않게 한다.

## 스토리 일정 생성과 검증

스토리 모드는 위 Day 표를 그대로 사용한다. 런타임 시작 전에 다음을 검증한다.

1. 객실에 등장하는 모든 예정 사건의 객실이 명부에 포함되어 있다.
2. 예정 사건과 같은 표면을 점유하는 일감이 없다.
3. 객실마다 충돌하지 않는 일반 일감이 최소 하나 있다.
4. 세탁실 사건이 있는 Day에는 수건 세탁 단계가 존재한다.
5. 외부 계단 사건이 있는 Day에는 쓰레기 폐기 단계가 존재한다.
6. 프런트 사건이 있는 Day에는 시작 또는 마감 명부 확인 동선이 존재한다.
7. 두 사건이 같은 객실에 있으면 서로 다른 방문 차례에 순차 배치할 수 있다.

검증 실패 시 일감을 조용히 삭제하거나 사건을 다른 방으로 옮기지 않고 개발 오류로 보고한다.

## Infinity 명부 생성

Infinity에서는 사건을 먼저 추첨하고 객실 명부를 나중에 만든다.

1. 메인 사건과 production 사건을 추첨하고 세이브한다.
2. 객실형 사건이 선택할 실제 객실과 장면을 확정한다.
3. 사건이 등장하는 모든 객실을 명부에 먼저 넣는다.
4. 객실이 두 개보다 적으면 시드 기반으로 일반 객실을 추가해 기본 두 객실을 채운다.
5. 각 객실의 기본 일감 프로필에서 사건과 충돌하는 일감을 제거한다.
6. 제거 후 일반 일감이 하나도 없으면 안전한 확정 일감으로 대체한다.
7. 최종 명부와 일감 구성을 세이브해 불러오기 후 바뀌지 않게 한다.

사건 ID의 이름으로 객실을 추측하지 않는다. `room_108_tv_ghost`처럼 레거시 ID와 현재 배치 객실이 다른 사건이 있으므로, 명부 포함 여부는 `anomaly_registry.gd`의 실제 placement 장면과 선택된 장면을 기준으로 계산한다.

예외 처리:

- 이불 속 아이가 105호나 108호에 선택되면 이불 정리를 제거하고, 안전한 벽 닦기 또는 쓰레기 정리를 유지한다.
- 샤워 커튼의 다리가 선택한 욕실은 반드시 명부 객실에 포함하고, 수건 뭉치는 커튼과 떨어진 위치를 사용한다.
- 붉은 세탁기가 선택되면 적어도 한 객실에 수건 수거·세탁·반환 일감을 둔다.
- 108호 전화가 선택되면 108호를 명부에 포함하고, 108호 완료 후 프런트 복귀 시 전화를 시작한다.
- 프런트·복도·외부 계단의 사건은 각각 명부 확인, 객실 이동과 쓰레기 폐기 동선으로 접근 이유를 보장한다.

## 세이브 데이터

근무 중 저장에는 최소한 다음 상태가 포함되어야 한다.

```gdscript
{
	"work_order": {
		"day": 6,
		"assigned_room_ids": ["room_106", "room_107"],
		"crossed_room_ids": ["room_107"],
		"manifest_read": true,
		"work_finished": false,
		"room_task_states": {
			"room_106": {
				"trash": "done",
				"loose_towels": "ready_to_return",
				"blood_wall": "done"
			},
			"room_107": {
				"trash": "done",
				"loose_towels": "done",
				"closet_clothes": "done"
			}
		},
		"work_cargo": {
			"trash_room_ids": [],
			"dirty_towel_room_ids": [],
			"clean_towel_room_ids": ["room_106"],
			"lost_clothing_room_ids": ["room_107"]
		}

```

펜 애니메이션 도중 저장하거나 종료해도 `crossed_room_ids`를 기준으로 이미 지운 번호를 다시 지우지 않는다. 애니메이션은 저장의 진실 원천이 아니라 상태를 보여 주는 연출이다.

## UI와 연출 원칙

- 명부는 객실 번호 외에 일감 정답을 알려 주지 않는다.
- 일반 일감 완료 팝업과 토스트를 띄우지 않는다.
- 사물이 사라지거나 정돈된 사진으로 바뀌는 상태 변화와 짧은 사물음만 사용한다.
- 객실 완료를 HUD 체크 표시로 실시간 공개하지 않는다.
- 프런트 명부에서만 펜으로 객실 번호를 지운다.
- `Do not disturb`는 최근 109호 구현과 같은 작은 하단 안내를 사용한다.
- 평범한 일감의 연출을 과장하거나 축하 효과를 넣지 않는다.
- 한국어와 영어의 명부, 버튼, 핫스폿과 `Do not disturb` 문구를 항상 함께 추가한다.

## 이미지 레이어 제작 원칙

- 일반 일감은 원본 사진을 직접 수정하지 않고 원본과 같은 캔버스의 투명 PNG를 쌓아 표현한다.
- 정상·정리 완료 상태는 원본 사진만 보이는 `base_only`로 둔다.
- 어지러운 이불은 침대 표면 전체를 교체하는 레이어 한 장으로 만들고, 완료 시 레이어를 숨긴다.
- 쓰레기는 컵, 종이와 포장지처럼 클릭 단위마다 별도 레이어로 만들어 하나씩 사라지게 한다.
- 수건, 옷과 벽 얼룩도 서로 다른 슬롯으로 분리한다.
- 레이어에는 원본 장면의 원근, 광원 방향, 접촉 그림자, 노출, 입자감과 렌즈 흐림을 이미 반영한다.
- 런타임에서는 레이어를 확대하거나 위치를 다시 맞추지 않고 원본 사진과 같은 사각형에 그대로 그린다.
- 일반 일감 레이어는 z-index `10~20`, 엔티티·기현상은 `100 이상`을 사용한다.
- 엔티티나 기현상이 같은 표면을 점유하면 해당 일반 일감 레이어와 핫스폿을 함께 숨긴다.
- 실제 파일 규격과 Room 105 프로토타입은 [호텔 일감 이미지 레이어](../resource/images/tasks/README.md)를 따른다.

## 테스트 기준

### 단위 테스트

- Day별 고정 객실 목록이 표와 일치한다.
- 명부에 없는 105~108호는 `can_enter_room()`이 `false`다.
- 세탁실은 객실 목록과 무관하게 항상 출입 가능하다.
- 객실 일감이 완료되기 전에는 번호를 지울 수 없다.
- 완료된 객실 번호를 한 번만 지운다.
- 모든 번호를 지운 뒤에만 `업무 완료`가 활성화된다.
- 수건 일감이 `collected → processing → ready_to_return → done`으로 진행된다.
- 업무 화물이 Hand 인벤토리를 변경하지 않는다.
- 사건과 일감의 표면 충돌 검증이 잘못된 일정에서 실패한다.

### 스모크 테스트

- 명부에 없는 문을 누르면 장면 이동 없이 문손잡이 소리와 `Do not disturb` 안내가 나온다.
- 명부에 있는 문은 기존 객실 장면으로 이동한다.
- 프런트 직접 이동을 포함한 모든 객실 진입 경로에 같은 권한이 적용된다.
- Day 2의 105호에는 옷장 옷 일감이 없다.
- Day 3의 107호에는 이불 일감이 없다.
- Day 4의 전화는 108호 완료 뒤 프런트 복귀 시 시작한다.
- Day 5의 일반 수건 세탁과 붉은 세탁기가 서로 다른 핫스폿을 사용한다.
- Day 6의 첫 106호 욕실 방문에는 아이가, 수건 세탁 후 재방문에는 거울이 순차적으로 나타난다.
- 활성 사건이 있는 장면에서는 일반 일감 핫스폿이 사건 핫스폿을 가리지 않는다.
- 저장 후 불러와도 객실 목록, 일감 단계와 명부의 펜 표시가 유지된다.

## 구현 순서

1. `HotelWorkOrderDefinition`과 `HotelWorkOrderManager`를 추가한다.
2. 스토리 Day별 객실 명부를 데이터로 등록한다.
3. 기존 109호 잠금 방식을 105~108호의 공용 출입 가드로 일반화한다.
4. 프런트 명부 UI와 펜 긋기 상태를 구현한다.
5. 객실별 기본 일감 프로필과 업무 화물 상태를 추가한다.
6. 쓰레기 폐기와 수건 수거·세탁·반환의 다단계 행동을 연결한다.
7. 사건의 점유 표면과 일감 충돌 검증을 추가한다.
8. 스토리 Day 2~7의 사건 시작 시점을 일감 동선에 맞춘다.
9. Infinity 사건 선추첨 후 명부 생성기를 추가한다.
10. 한국어·영어 번역, 저장 복구, 단위 및 스모크 테스트를 완성한다.

## 완료 정의

이 설계의 구현은 다음을 모두 만족해야 완료다.

- 플레이어는 매일 프런트 명부에서 객실 번호만 확인한다.
- 명부에 없는 일반 객실에는 들어갈 수 없다.
- 세탁실은 명부와 관계없이 출입할 수 있다.
- 여섯 종류의 확정 일감이 별도 설명 없이 정상 사물 상호작용으로 작동한다.
- 모든 객실형 엔티티와 기현상에는 해당 객실에 들어갈 업무상 이유가 있다.
- 일감과 사건이 같은 표면이나 핫스폿을 점유하지 않는다.
- 완료한 객실은 프런트에서 펜으로 하나씩 지워진다.
- 모든 객실을 지운 뒤에만 `업무 완료` 버튼이 활성화된다.
- 저장·불러오기와 Infinity에서도 그날 명부와 사건 배치가 바뀌지 않는다.
