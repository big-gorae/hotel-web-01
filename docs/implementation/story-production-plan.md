# 확정 이야기 구현 계획

마지막 갱신: 2026-08-06

## 범위

이 문서는 [확정 사항 원장](../anomaly-bible/confirmed-decisions.md)의 현재 이야기 설정을 런타임 전달 단위로 관리한다. 이전의 도박 빚, 불법적인 일, 동생 명의 근무와 `동생을 찾으러 왔다고 말하지 마` 설정은 폐기한다.

언니가 된 구체 엔티티, 외형, 반복 출현 방식, 플레이어가 죽이는 방법과 사후 정체 확인 물증은 아직 확정하지 않는다. 해당 내용이 정해지기 전에는 기존 엔티티에 언니 정체를 임의로 연결하지 않는다.

## 플레이어가 반드시 이해해야 하는 사실

1. 플레이어는 호텔에서 일하거나 방문한 적이 없다.
2. 호텔은 플레이어에게 전화해 연락이 끊긴 언니의 이름으로 부른다.
3. 언니의 미지급 급여와 퇴직금은 5천만 원이 넘는다고 안내된다.
4. 언니는 연락되지 않고 부모도 행방을 모른다.
5. 플레이어는 언니의 마지막 행적을 확인하기 위해 자신이 언니라고 거짓말하고 근무를 시작한다.
6. 언니는 형사이며, 비정상적인 급여, 연락되지 않는 사장과 사라진 직원들을 조사하려 잠복 취업했다.
7. 룰북에는 사람을 109호로 유도하는 거짓 지침이 있다.
8. 언니는 그 지침을 따른 뒤 기현상 때문에 엔티티가 됐다.
9. 언니는 완전히 변하기 전에 거짓 지침 번호를 경고했지만 숫자는 피로 가려졌다.
10. 관리자는 언니의 경고를 9번 지침으로 편입한 뒤 10번에서 무시하라고 적었다.
11. 언니가 된 엔티티는 정체를 알아볼 수 없는 모습으로 반복 등장하며, 주인공이 결국 직접 죽인다.

## Day별 전달표

| Day | beat ID | 현재 텍스트 전달 |
| ---: | --- | --- |
| 1 | `story.call_uses_sister_name` | 호텔이 플레이어를 언니 이름으로 부르고 5천만 원이 넘는 미지급 급여와 퇴직금을 안내 |
| 1 | `story.player_claims_sister_identity` | 연락 두절된 언니의 흔적을 쫓기 위해 플레이어가 언니라고 거짓말 |
| 2 | `story.sister_employment_record` | 언니 명의 근무 기록, 비정상적인 급여와 연락되지 않는 사장 |
| 3 | `story.sister_undercover_investigation` | 형사인 언니가 호텔에 잠복 취업한 이유 |
| 4 | `story.blood_obscured_false_rule_warning` | 피로 번호가 가려진 언니의 경고와 9번을 무시하라는 반박 |
| 5 | `story.sister_traced_missing_workers` | 큰돈을 받은 뒤 자진 퇴사 처리되고 연락이 끊긴 직원들 |
| 6 | `story.sister_last_room_109_recording` | 언니가 지침을 따라 109호에 들어간다는 마지막 녹음 |
| 7 | `story.room_109_invitation_wording` | 언니의 기록 마지막 장에 6번 지침 원문이 그대로 남아 있음 |

한국어와 영어는 `story.day.{day}.line.{line}` 키를 동일하게 유지한다. 기타 locale은 영어 fallback을 사용할 수 있다.

## 룰북 번호

| 번호 | ID | 작성자 | 문장 | Day |
| ---: | --- | --- | --- | ---: |
| 6 | `enter_open_room_109` | 관리자 또는 109호 안의 미확인 화자 | `109호가 열려 있다면 방에 들어오십시오.` | 3 |
| 9 | `sister_bloodied_false_rule_warning` | 언니 | `■■번 항목은 거짓말이야.` | 3 |
| 10 | `ignore_sister_warning` | 관리자 | `9번 지침은 무시하시오.` | 3 |

- 6번은 거짓 지침이다.
- 9번 문장의 `■■`는 텍스트 fallback이다. 최종 페이지 이미지에서는 실제 번호 위를 피가 가려야 한다.
- 9번은 언니의 필체, 6번과 10번은 같은 관리자 인쇄체로 구분한다.
- `들어오십시오`를 `들어가십시오`로 교정하지 않는다.
- UI나 대사가 문장 시점의 의미를 별도 팝업으로 설명하지 않는다.

## 저장 계약

스토리 전달은 `scripts/story/story_delivery_manager.gd`의 beat ID를 저장한다.

```text
completed_story_beat_ids
unlocked_evidence_ids
current_story_sequence_id
story_sequence_step
```

이전 정사의 beat ID를 가진 기존 세이브는 해당 Day의 새 beat를 미완료로 보므로 새 문장을 한 번 재생할 수 있다. 정식 출시 전 데이터 변경으로 허용하며, 이후 beat ID를 다시 바꾸지 않는다.

## 미확정 후속 구현

- 언니가 된 엔티티의 ID와 비주얼
- 스토리 모드 반복 출현 Day와 행동
- 언니임을 미리 추측할 수 없게 하는 표현 기준
- 플레이어가 직접 죽이는 상호작용
- 죽인 뒤 언니임을 확인하는 물증과 장면
- 정체 확인 이후 마지막 선택과 결말

이 항목들이 확정되기 전에는 Day 7의 기존 109호 통과 존재, 돼지 가면 남자나 다른 기존 엔티티를 언니로 지정하지 않는다.

## QA

- 한국어와 영어가 모두 언니 이름으로 걸려 온 전화와 5천만 원 이상의 금액을 전달하는지 확인
- 플레이어가 과거 호텔에서 일했거나 방문했다는 문장이 남아 있지 않은지 확인
- 빚과 불법적인 일이 근무 수락 동기로 남아 있지 않은지 확인
- Day 3 룰북에 6번, 9번, 10번이 순서대로 보이는지 확인
- 6번의 `들어오십시오` / `come inside` 시점이 번역에서도 유지되는지 확인
- 9번의 실제 거짓 지침 번호가 텍스트나 이미지에서 노출되지 않는지 확인
- 언니의 필체와 관리자 문체가 최종 페이지 이미지에서 구분되는지 확인
- 미확정 엔티티를 기존 자산에 임의로 연결하지 않았는지 확인
